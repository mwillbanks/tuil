## Create an application

Use `createApp` to define the component, theme, terminal mode, and runtime
services in one boundary. Render it with `@mwillbanks/tuil-ink`; tests use the
same application through `renderTuil`.

```tsx
const app = createApp({
  id: "tasks",
  component: Tasks,
  terminal: { mode: "interactive" },
})

await render(app)
```

Choose `static` mode for pipelines and redirected output. Interactive code must
also expose a deterministic static fallback.

## Compose features

Register commands, hotkeys, routes, plugins, and event subscribers during
application setup and dispose registrations during teardown. Forms own typed
values and validation; operations own asynchronous progress and cancellation;
workflows own persisted multi-step state.

Components can use the runtime's typed and observable surfaces directly:

```tsx
import { useApp, useExtensions } from "@mwillbanks/tuil"
import { createTheme } from "@mwillbanks/tuil-theme"
import { Text } from "ink"

function Status() {
  const app = useApp<{ "task:saved": { id: string } }>()
  const routes = useExtensions("routes")

  return <Text>{routes.length} routes</Text>
}

await app.events.emit("task:saved", { id: "task-1" })
app.themeController.set((theme) =>
  createTheme(theme, { id: "high-contrast" })
)
```

Plugin manager disposal is final. Create a new application runtime instead of
registering or initializing plugins after shutdown.

## Verify behavior

Use semantic roles and labels instead of terminal coordinates. Cover keyboard
navigation, focus traps, route changes, form validation, operation
cancellation, resizing, and the non-interactive fallback.
