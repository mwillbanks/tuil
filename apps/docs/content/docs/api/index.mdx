| `@mwillbanks/tuil-ink` | Ink renderer, primitives, overlays, and terminal input |
| `@mwillbanks/tuil-form` | Typed forms, validation, and controlled fields |
| `@mwillbanks/tuil-router` | Typed routes and navigation |
| `@mwillbanks/tuil-operations` | Observable async work and cancellation |
| `@mwillbanks/tuil-workflow` | Persistent step workflows |
| `@mwillbanks/tuil-plugin` | Plugin lifecycle and extension points |
| `@mwillbanks/tuil-theme` | Theme definitions and registries |
| `@mwillbanks/tuil-events` | Typed declarations, dispatch, routing, redaction, and observation |
| `@mwillbanks/tuil-testing` | Portable stories and semantic assertions |
| `@mwillbanks/tuil-testing-ink` | Ink-backed tuil test renderer |
| `@mwillbanks/tuil-story` | Story sessions, bridge, snapshots, and browser adapters |

Import only from package exports. Runtime packages do not depend on Storybook
or documentation tooling; optional browser integrations live under the story
package's explicit adapter entry points.

## Discover and resolve plugins

```ts
import {
  createPlugin,
  PluginRegistry,
} from "@mwillbanks/tuil-plugin"

const plugins = new PluginRegistry()
const registration = plugins.register({
  plugin: createPlugin({
    id: "audit",
    version: "1.0.0",
    setup: ({ events }) =>
      events.observe((event) => console.error(event.type)),
  }),
  tags: ["observability"],
})

const [audit] = plugins.resolve(["audit"])
// Register `audit` with the application plugin manager.
registration.dispose()
```

Registry registration is disposable. `resolve()` validates dependencies and
returns them before their consumers.

## Resolve a built-in theme

```ts
import { createApp } from "@mwillbanks/tuil"
import {
  createDefaultThemeRegistry,
  createTheme,
} from "@mwillbanks/tuil-theme"

const themes = createDefaultThemeRegistry()
const app = createApp({
  component: Dashboard,
  theme: themes.resolve("default-light"),
})
```

Use `new ThemeRegistry().register(...)` for application-owned theme catalogs;
the returned registration is disposable.

Switch a running application through its capability-aware controller:

```ts
app.themeController.set(themes.resolve("default-light"))
app.themeController.set((current) =>
  createTheme(current, { colors: { primary: { foreground: "yellow" } } })
)
```

Ink subscribes to the controller, so mounted components using `useTheme()`
rerender. Every selected theme is normalized for the active terminal.

## Render a full-screen image workspace

```tsx
import {
  Box,
  render,
  TerminalImage,
  useTerminalSize,
  type TerminalImageSource,
} from "@mwillbanks/tuil-ink"

function Splash({ logo }: { logo: TerminalImageSource }) {
  const { width, height } = useTerminalSize()
  return (
    <Box width={width} height={height} alignItems="center" justifyContent="center">
      <TerminalImage source={logo} alt="Application logo" columns={28} />
    </Box>
  )
}

const instance = await render(app, { alternateScreen: true })
```

`TerminalImage` accepts validated RGBA pixel data, scales it to terminal
columns, and uses 24-bit half-block rendering with a grayscale fallback.
`useTerminalSize()` tracks both terminal dimensions across resize events.
`alternateScreen` is honored only for interactive TTY output, and the renderer
restores the original buffer when the Ink instance exits.

## Consume typed events and extensions

`createApp` preserves application event payload types through `app.events`.
Components can request the same surface with `useApp<MyEvents>()` and call
`on()` or `emit()` without losing payload types. Extension registries expose
typed `register()`, `values()`, and `observe()` operations. Use
`useExtensions("routes")` in React code to rerender when contributions are
registered or disposed.

## Mount runtime devtools

```tsx
import { TuilDevtools } from "@mwillbanks/tuil-devtools"

export function App() {
  return (
    <>
      <Dashboard />
      <TuilDevtools initiallyOpen />
    </>
  )
}
```

The component is a hook-free `null` in production. In development, use
Ctrl+Shift+D to toggle the inspector.

## Generate story snapshots and documentation

```tsx
import {
  defineTuilStories,
  generateStoryCatalogDocumentation,
  generateStoryCatalogSnapshots,
  TuilStoryCatalog,
} from "@mwillbanks/tuil-story"

const catalog = new TuilStoryCatalog()
catalog.register("status", "Status", defineTuilStories({
  component: Status,
  stories: {
    Ready: { args: { state: "ready" } },
  },
}))

const signal = AbortSignal.timeout(5_000)
const snapshots = await generateStoryCatalogSnapshots(catalog, { signal })
const markdown = await generateStoryCatalogDocumentation(catalog, { signal })
```

Catalog snapshots contain deterministic frames, semantics, focus, and terminal
controls. Live request/session frames additionally expose bounded events and
actions.
