---
title: Architecture
description: Runtime ownership, rendering boundaries, and extension topology.
---

`createApp` owns one `TuilRuntime`. The runtime composes capabilities, theme,
events, commands, hotkeys, focus, routing, plugins, operations, and extensions.
The Ink adapter provides rendering and input without becoming the public
application model.

Portable stories sit above the runtime boundary. A story request creates an
isolated application, applies terminal capabilities and theme, replays bounded
input, captures semantic and ANSI frames, and always closes the renderer.
Fumadocs, Storybook, the showcase, and the playground consume that same story
catalog.

Plugins register through typed, disposable, observable extension registries.
`useExtensions()` connects those registries to React rendering. Applications
retain ownership of plugin activation and teardown; disposal is terminal for a
plugin manager, aborts its shared signal, and prevents later registration or
initialization.

The runtime exposes the full typed event bus to application components. Event
declarations, listeners, emission, bounded observation history, and redaction
therefore share one contract instead of splitting UI and host capabilities.

Theme selection is runtime state. `ThemeController` publishes live changes;
the Ink adapter subscribes its `ThemeProvider`, and every replacement is
normalized against the terminal's color, Unicode, and motion capabilities.
